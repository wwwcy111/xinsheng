# 【码道新声】公网部署说明（GitHub Pages + 腾讯云 CloudBase 云托管）

本文档用于把演示站点发布到公网，方便评委在电脑和手机上直接访问。
前端仍由 GitHub Pages 托管，后端改用腾讯云 CloudBase 云托管（国内机房，访问最快）。

## 一、门槛与费用（先看这里）

| 项目 | 要求 |
| --- | --- |
| 腾讯云账号 | 需要完成**实名认证**（身份证 + 人脸，免费，约 5 分钟） |
| 支付方式 | 不需要信用卡；如需充值可用微信/支付宝 |
| 环境套餐 | 可选「免费体验版」（0 元/月） |
| 云托管计费 | 按量计费，最小规格约 **0.03 元/小时**；无请求自动缩容到 0，不产生费用 |
| 典型演示成本 | 一次预热 + 答辩 2-3 小时，通常**几分钱到几毛钱** |

> 官方说明：云托管的 CPU/内存用量不计入云开发套餐资源点，需在环境中开启「超限按量」，否则服务会被停止。开通时按控制台提示操作即可。

## 二、开通云开发环境

1. 打开 `https://tcb.cloud.tencent.com/dev`，用微信扫码登录腾讯云。
2. 首次使用会提示完成**实名认证**，按页面指引提交身份证与人脸核验。
3. 创建环境：地域选 **上海**（云托管当前支持上海），套餐选 **免费体验版（0 元）**。
4. 环境创建完成后，在环境详情中确认已开启「超限按量」（否则云托管服务会被停止）。

## 三、部署后端（云托管）

仓库根目录已提供 `Dockerfile`（构建上下文为仓库根，端口 8080），可直接被云托管识别。

### 方式一：一键链接（推荐）

在浏览器打开下面链接，页面会自动预填仓库、分支、服务名与端口：

```text
https://tcb.cloud.tencent.com/dev#/platform-run/service/create?type=git&repoUrl=https://github.com/wwwcy111/xinsheng&repoBranch=main&serverName=xinsheng-api&port=8080
```

确认无误后点击「部署」。若链接未预填完整，按方式二手动填写。

### 方式二：手动创建

1. 进入环境 → 左侧 **云托管** → **新建服务**。
2. 部署方式选择 **通过公开 Git 仓库地址部署**（无需授权 GitHub）。
3. 填写：
   - 仓库地址：`https://github.com/wwwcy111/xinsheng`
   - 分支：`main`
   - 服务名称：`xinsheng-api`
   - 服务端口：`8080`
   - 构建目录：留空（使用仓库根目录 `Dockerfile`）；也可填 `backend`（使用 `backend/Dockerfile`）
4. 规格选最小：CPU **0.25 核**、内存 **0.5 GB**；最小实例数 `0`，最大实例数 `1`。
5. 点击创建并等待构建完成（首次约 3-8 分钟）。

> 若构建日志提示拉取 GitHub 超时，改用「部署容器镜像」或本地 `tcb cloudrun deploy`（见第九节）。

## 四、配置环境变量

服务创建后，进入 **服务配置 → 环境变量**，逐条添加：

| 变量名 | 值 | 说明 |
| --- | --- | --- |
| `SECRET_KEY` | `xinsheng-demo-fixed-key-2026` | 固定演示密钥，重启后 Token 不失效 |
| `AI_ENABLED` | `false` | 走本地模板兜底，演示稳定 |
| `CACHE_REPLAY` | `true` | 开启结果缓存回放 |
| `CORS_ORIGINS` | `*` | 允许 GitHub Pages 跨域 |
| `TOKEN_EXPIRE_MINUTES` | `120` | Token 有效期 |
| `MAX_UPLOAD_MB` | `20` | 与云托管 20M 包体上限一致 |

保存后重新部署一次版本，让环境变量生效。

## 五、获取访问地址并验证

1. 在服务详情页顶部复制系统默认域名（形如 `https://xxxx.sh.run.tcloudbase.com`，以页面实际显示为准）。
2. 浏览器访问 `https://<域名>/api/v1/health`，返回 `{"code":0,"message":"ok",...}` 即为成功。
3. 打开 `https://<域名>/docs` 可查看接口文档。

## 六、对接前端（GitHub Pages）

1. 打开仓库 **Settings → Secrets and variables → Actions → Variables**。
2. 编辑或新建变量 `VITE_API_BASE`，值为 `https://<域名>/api/v1`。
3. 打开 **Actions** → 选择 `Deploy Frontend to GitHub Pages` → **Run workflow**（分支 `main`）。
4. 等待 `build` 与 `deploy` 均变绿，访问 `https://wwwcy111.github.io/xinsheng/`。

> `VITE_API_BASE` 只在构建时注入，改完必须重跑一次工作流。

## 七、验收清单

- [ ] `https://<域名>/api/v1/health` 返回 `code = 0`
- [ ] 前端页面可打开，浏览器控制台无跨域报错
- [ ] 注册新账号 → 选择兴趣标签 → 进入首页
- [ ] 搭子匹配返回匹配分、理由与 3 条破冰话题
- [ ] 上传笔记图片 → 生成思维导图、摘要、练习题
- [ ] 生活板块可发布二手、失物招领、活动报名
- [ ] 手机浏览器访问同一地址正常

## 八、成本控制

1. 最小实例数保持 `0`：无访问时缩容到 0，不计 CPU/内存费用。
2. 答辩结束后在控制台**停止服务**或删除服务，避免长期运行产生费用。
3. 关闭不需要的自动部署，减少重复构建。
4. 在环境「用量统计」页查看资源点消耗，发现异常立即停止服务。

## 九、数据与文件说明

- 容器文件系统为**临时盘**：重新部署或实例重建后，SQLite 数据与 `uploads/` 文件会清空。
- 应用启动时会自动建表并写入种子标签（`backend/app/main.py` 的 lifespan），因此重启后功能可用，但**已注册账号需要重新注册**。
- 演示前建议提前注册账号并走一遍完整流程。
- 若需要数据持久化，可在环境中开通 PostgreSQL 数据库并把 `DATABASE_URL` 改为连接串（需额外改造 ORM 字段类型）。

## 十、常见问题

| 现象 | 处理 |
| --- | --- |
| 服务创建后立即停止 | 环境未开启「超限按量」，去环境设置中开启 |
| 构建失败，日志显示拉取 GitHub 超时 | 改用容器镜像方式或 `tcb cloudrun deploy` |
| 访问域名 404 / 502 | 确认服务端口为 `8080`、容器监听 `0.0.0.0:8080`，查看应用日志 |
| 前端接口报跨域 | 确认 `CORS_ORIGINS=*` 已生效并重新部署版本 |
| 上传文件报 413 | 云托管包体上限 20M，与 `MAX_UPLOAD_MB=20` 一致，压缩图片后重试 |
| 接口偶发 504 | 云托管请求超时 60s，首次冷启动较慢，重试即可 |
