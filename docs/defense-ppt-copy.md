## 一、核心叙事主线

**一句话定位**

> 新声，是大一新生在陌生校园里的第一站：用一份画像，串起破冰、学业与生活，让 AI 在新生最需要开口、最需要减负、最需要落地的时刻出现。

**三句话亮点**

1. **一站式多场景**：不是三个功能放进一个导航栏，而是同一份画像在三个场景里持续生效。
2. **华为云 AI 赋能**：两条核心链路——搭子匹配与笔记解析，规则兜底、模型增强、全程可降级。
3. **高校落地价值**：低成本、可复制、可运营，一个学院试点即可跑通，一套配置可复制到全校。

**冲奖记忆点（建议反复出现）**

> 让每一个大一新生，在陌生的校园里，第一次被看见。

### P3 痛点：新生真正卡住的地方

**上屏文案**

- **第一次开口**：想认识人，但不知道聊什么，社恐成本高。
- **第一次独立复习**：笔记零散，抓不住重点，练习无反馈。

**演讲备注（40 秒）**

我们拆解了新生最高频的三个卡点。注意，它们不是三个孤立需求：一个愿意开口的人，更可能找到自习搭子；一个会整理笔记的人，更可能持续参与学习活动。所以它们应该被一个平台接住。

**视觉建议**

### P6 亮点一：一站式多场景

**上屏文案**

> 一站式不是把三个功能放在一个导航栏，
> 而是让同一份画像在三个场景里持续生效。

- 画像 → 匹配：标签相似度、性格互补度
- 画像 → 学习：同专业、同课程的学习搭子
- 画像 → 生活：社团与活动按兴趣推荐
- 场景闭环：认识同学 → 一起自习 → 参加活动

**演讲备注（50 秒）**

这是我们的第一个差异化。很多校园产品是“功能集合”，用户注册完，数据互不相通。新声的画像是一次录入、三处复用。新生在破冰页选的“摄影”，会出现在活动推荐里；在笔记页选的课程，会影响学习搭子的推荐。场景之间是流动的。

**视觉建议**

一张“数据流动”示意图：画像节点向三个模块发出箭头，箭头带光效。

### P7 亮点二：华为云 AI 赋能

**上屏文案**

- **两条核心链路**：搭子匹配、笔记解析
- **统一 AI 网关**：主备模型切换、JSON Schema 校验、8s/30s 超时
- **三层稳定保障**：规则兜底 → 模板兜底 → 缓存回放
- **双层内容安全**：发布过滤 + AI 产出过滤

**演讲备注（50 秒）**

我们不是把大模型当一个聊天框，而是把它嵌进业务流程。所有调用收敛到一个 AI 网关：统一鉴权、统一超时、统一 JSON 校验。模型不稳定时，匹配有规则分，笔记有模板，现场断网还有缓存回放。答辩现场最怕的不是模型慢，而是演示断掉，所以我们把“不断”当成一级需求。

**视觉建议**

网关居中，左侧两条业务链路，右侧华为云 ModelArts / OCR / OBS 图标。

### P8 核心 AI 能力一：搭子匹配

**上屏文案**

- **规则负责准**：标签相似 55% + 性格互补 30% + 社交偏好 15%
- **模型负责暖**：生成匹配理由 + 3 条可直接发送的破冰话题
- **结果可解释**：每条推荐都能说清“为什么是你们俩”
- **演示效果**：匹配分环形展示，话题一键复制

**演讲备注（50 秒）**

搭子匹配最怕两件事：匹配不准，和匹配了却不敢开口。我们用规则保证准，用大模型解决开口。提示词里明确要求理由必须引用共同标签，开场白必须是同学之间自然开口，不许“您好很高兴认识您”。这三条话题，就是新生从“看到”到“聊起来”的最后一百米。

**视觉建议**

左侧评分公式，右侧聊天界面示意，三条话题气泡。

---

### P9 核心 AI 能力二：笔记解析

**上屏文案**

- 上传图片/PDF → OCR → 结构化 JSON
- 一次生成：**思维导图 + 核心考点 + 5 道以上练习题**
- 只依据原文，禁止编造公式与结论
- 失败可重试，模型不可用时模板兜底

**演讲备注（50 秒）**

笔记解析解决的是“复习从哪开始”。我们把非结构化的笔记，变成三样能直接用的东西：一张导图看结构，一组考点抓重点，一套练习题做反馈。提示词里最关键的一句是“只依据 OCR 文本，不得编造”。这是我们对大模型幻觉的正面约束。

**视觉建议**

左侧上传框，右侧三张结果卡片：导图树、考点列表、练习题。

### P10 技术架构：轻量但不简陋

**上屏文案**

- 前端：Vue 3 + Vite + Pinia，移动优先，520px 卡片式演示
- 后端：FastAPI 模块化单体，单进程可跑，50 并发以内
- 数据：SQLite 起步，可平滑切 MySQL；12 张表覆盖三场景
- 云能力：华为云大模型 + OCR + OBS，配置切换不改业务代码

**演讲备注（40 秒）**

竞赛项目最容易犯的错，是为了“技术感”引入一堆重型组件，最后演示跑不起来。我们反其道而行：模块化单体、零消息队列、零 Redis，靠数据库状态机和条件更新保证一致性。轻量不是能力弱，而是把复杂度留给业务。

**视觉建议**

四层架构图：客户端 → 接入层 → 应用层 → 数据与云能力。

### P12 亮点三：高校落地价值

**上屏文案**

- **对新生**：降低开口门槛、减少复习盲目、聚合生活信息

## 三、评委问答预案

### Q1：和校园墙、QQ 群有什么区别？

**回答要点**

- 校园墙解决曝光，群聊解决即时，新声解决“第一次”的连续性；
- 核心差异是画像驱动：一次录入，匹配、学习、活动三处复用；
- 场景闭环：从认识到一起自习，再到线下活动，信息不沉底。

### Q2：AI 匹配分数准不准？会不会歧视？

**回答要点**

- 分数由可解释规则主导：标签相似 55%、性格互补 30%、社交偏好 15%；
- 大模型只负责理由与话题，不单独决定推荐结果；
- 候选池排除已屏蔽、7 日内已推荐对象，避免重复打扰；
- 不采集性别、外貌、家庭条件等敏感维度。

### Q3：大模型幻觉怎么处理？

**回答要点**

- 笔记 Prompt 明确“只依据 OCR 文本，不得编造”；
- 输出做 JSON Schema 校验，字段缺失或结构不符则重试一次；
- 仍失败走模板兜底，页面标注“降级结果”；
- 内容安全双层过滤，命中敏感词丢弃重试。

### Q4：用户隐私怎么保护？

**回答要点**

- 只采集昵称、学号后四位、兴趣标签，不采集身份证；
- 联系方式按关系展示，日志脱敏；
- 口令 PBKDF2 哈希存储，JWT 2 小时过期；
- AI 输入不包含学号与联系方式。

### Q5：为什么选择华为云？

**回答要点**

- 大模型、OCR、OBS、内容审核在同一云体系，鉴权与计费统一；
- OpenAI 兼容接口，切换模型不改业务代码；
- CodeArts 覆盖开发、构建、部署，适合高校团队快速迭代；
- 学校已有华为云资源时，落地成本更低。

### Q6：项目可持续吗？会不会比赛结束就停了？

**回答要点**

- 轻量架构，单实例即可运行，运维成本低；
- 学院试点 → 校级推广 → 社团运营，有明确落地路径；
- 数据可沉淀：活动、笔记、搭子关系形成校园内容资产；
- 后续可扩展二手担保、活动签到、学院看板等增值能力。

### Q7：冷启动没有用户怎么办？

**回答要点**

- 新生周线下扫码 + 班级群 + 社团合作；
- 预置 23 个兴趣标签与演示活动，首屏不空；
- 匹配需要至少两位完善画像的用户，运营侧先组织种子用户；
- 单学院试点，密度优先于广度。
